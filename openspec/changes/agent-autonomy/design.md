# agent-autonomy — design

## Context

proposal.md's *Why* explains the motivation. The facts behind the design were
read on 2026-10-12:

- Steps that name the user were found by grepping `core/*.md`, `CLAUDE.md`,
  `openspec/config.yaml`, `core/skills/*/SKILL.md` and
  `.claude/commands/opsx/*.md` for `the user`, `ask`, `go-ahead`, `approv`,
  `confirm`, `wait for`, `remind`, `stop and` and `BLOCKED`. Each hit was then
  read in its passage. `openspec/config.yaml` holds no `context:` or `rules:`,
  and `CLAUDE.md` holds no such step.
- `bun/sync.ts` copies every Markdown file in `core/` into a consumer's
  `harness/`, so a new doc there reaches consumers on their next bump with no
  list to edit. Specs are not copied, which is why the class definitions
  cannot live only in a spec.
- `.claude/commands/opsx/*.md` were generated by OpenSpec 1.14.0 and committed
  whole in `f3d8a6d`. `openspec update` rewrites them, so a marker written
  into them would not survive.
- The card-questions change (harness#56, `task-board`) sets out what happens
  to a question that only the user can settle. `card` hands questions to that
  procedure, whatever form its revision takes, and restates none of it.
- `bun/board-state.ts` refuses an `after:` that names a directory on
  neither `main` nor its archive, and `board-state-hygiene.test.ts` runs it
  over the tree. An `after: [card-questions]` therefore fails `bun test` on
  this branch until harness#56 merges.

## Goals / Non-Goals

**Goals**

- Each critical-path step says what an unattended session does there, at the
  step.
- One place says what the three classes mean.
- An unclassified step fails safe.
- The vocabulary is pinned so that a typo cannot pass as a class.

**Non-Goals**

- Any change to how an attended session behaves.
- Any hook or setting.
- A detector for unmarked steps.

## The classification

wording, never a line number. "Unattended" is what the marker tells the
session to do in place of the step.

Two kinds of step were left unmarked. The first is a prohibition that cannot
stall the loop, such as "never move a card within that order: it is the
user's drag". The second is a step only an attended session can meet, such
as "If the user pauses to correct your style". `git-and-prs.md`'s bullet on
speech under the user's name belongs to the card-questions change.

## Decisions

### The classes live in one doc in `core/`, and each step carries its class

`core/autonomy.md` defines the classes. Each step names its class inline.
`sync.ts` copies the doc to consumers, which a spec would not reach, and a
marker at the step is read by the session that is at the step.

- *Alternative: a table of steps in the doc.* It would restate each step's
  wording away from the step, and it would drift the first time a step was
  reworded. The table above is this change's plan, not a shipped artefact.
- *Alternative: the classes only in `agent-autonomy`'s spec.* Consumers do not
  receive specs, and `feature-workflow.md`'s single-source rule puts agent
  rules in the docs `CLAUDE.md` indexes.

### A step with no marker is `card`

`card` fails safe. Nothing is done that the user did not see, and the answer
has a route back. A step classed `agent` by default would let every vendored
"ask the user" pass unseen. A step classed `user` by default would stop the
loop at OpenSpec's every "pause on ambiguity" with no way to resume.

### Unattended is declared by the prompt that starts the session

A session is unattended only when the prompt or brief that started it holds
this line, verbatim and on a line of its own:

```text
This session runs unattended.
```

The session looks for that exact line and nothing else.

- **Declared.** A runner starts a session with `/opsx:apply agent-autonomy`,
  followed by the line above. At the step "Wait for the user's go-ahead", the
  session reads the `agent` marker and opens the pull request itself.
- **Not declared.** The user writes "Apply agent-autonomy overnight, I'm
  asleep". The line is missing, so the session is attended, whatever the
  words suggest. At the same step it offers the pull request and waits.

Leaving the line out leads to a stall, never to an act the user did not want.
That is why the declaration is opt-in, and is never inferred from wording,
from `-p` or from the permission mode. An orchestrator copies the line into
each worker's brief, since a worker cannot see its parent's prompt.

- *Alternative: an environment variable set by the runner.* No hook reads it
  in this change, and the session would spend a tool call to learn it. Revisit
  when a hook needs to know, such as the turn gate.
- *Alternative: the `/goal` objective.* What `/goal` stores and shows to the
  session has not been checked. Revisit with the card *Formalise /goal in
  harness sessions*.

### A `user` step is never asked on a card

A yes on the card would not let the agent take the step, so the question
would unblock nothing and would only add to what the user has to read. The
step goes in the report as `BLOCKED`, and the user takes it in a session of
their own.

### The pull request opens over a Major or Critical left open

Unattended, a 🟠 Major or 🔴 Critical that the local review left open does not
hold back the pull request. This covers two cases:

- the session proposes to dismiss the finding, and the gate line reads `OPEN`;
- the finding is still unresolved after the third pass, and the gate line
  reads `BLOCKED`.

The body lists each such finding with its severity, its file and line, and
what it says. It then gives either the reason dismissal is proposed, or a
statement that the finding is still open. The user settled both cases on
harness#63, on the condition that every such finding is listed in the body
that way. A bare count does not meet the condition, and neither does a
finding listed without its reason or status. The merge is the user's, so a
finding left open is still read before it lands. The gate lines stay as
`local-review-loop` sets them, so the record of the review does not change.

### OpenSpec's commands are covered by a rule, not by edits

A prompt that names a stage is the request that stage's command waits for.
Every other ask in a command is `card`. Edits to
`.claude/commands/opsx/` would be lost on the next `openspec update`.

### The marker is `(unattended: <class> — <what instead>)`

The form is inline, so it travels with the step when the step is moved or
reworded. It is fixed, so a regular expression finds it across a line wrap.
It is short enough to sit inside an existing sentence. The class names are
lower-case words and never collide with prose.

### The vocabulary is pinned, but coverage is not

`bun/autonomy.test.ts` checks three things: every marker under `core/` names
a defined class, the doc defines exactly three, and `core/rules.md` links the
doc. The test exempts nothing under `core/`, since `rules.md` asks that a scan
be scoped by what it exempts. A check that every step naming the user carries
a marker would have to recognise "a step that names the user" in free prose,
and that is a guess. The default class covers what such a check would miss.

## Risks / Trade-offs

- [An unattended session reads `card` as leave to proceed on its own
  recommendation] → The doc says that the work waiting on the answer
  stops.
- [The markers lengthen the always-on `core/rules.md`] → The doc adds four
  inline markers and one link line. That is far under the ~350-line trigger
  in `context-budget`; measure the file in the apply.
- [An orchestrator forgets the declaration] → Its workers run attended, and
  they stall at the first step that waits. This is visible and safe.
- [The ordering is prose until harness#56 merges] → `.openspec.yaml` carries
  no `after:` on this branch, because one naming card-questions fails
  `bun test` (see *Context*). Task 1.0 adds it as the apply's first commit,
  and the apply itself waits for #56.
- [A consumer gets the doc before the card-questions hook] → A `card`
  question still reaches the session's report, which needs no hook.

## Migration Plan

One group, one harness pull request. Consumers receive the doc and the
markers through `sync.ts` on their next bump. To roll back, revert the pull
request: attended sessions never read the markers.
